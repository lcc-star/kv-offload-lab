# Swap kernel 数据布局复现实验

## 实验目的

验证 GPU 与 CPU 的 KV cache block 编号不相同时，`swap_blocks` 是否只复制映射指定的完整逻辑 block，并能把换出的数据恢复到任意 GPU block。

## 测试设计

测试张量使用项目中的 KV cache 布局：

```text
[K/V, layer, physical block, token, KV head, head dimension]
```

每个坐标填入唯一的 `int32` 值，使任何维度错位都能被精确检测。实验包含两组映射：

1. 换出：GPU block `1 -> 3`，GPU block `4 -> 0`。
2. 换入：CPU block `3 -> 2`，CPU block `0 -> 5`。

除目标 block 外，其余 block 必须保持原值。

## 运行方式

```bash
source .venv/bin/activate
CUDA_VISIBLE_DEVICES=0 python study/swap_kernel_repro/test_swap_kernel.py
```

## 修复前结果

两项测试均失败：

```text
test_non_identity_swap_out_copies_logical_blocks_only ... FAIL
test_round_trip_can_restore_to_different_gpu_blocks ... FAIL

Ran 2 tests
FAILED (failures=2)
```

失败发生在目标 block 的逐元素比较，CUDA 扩展编译、加载和 kernel 执行均正常完成。

## 根因与修复

物理 block 位于 KV cache 张量的第 3 维。一个逻辑 block 并不是整块连续内存，而是分布在所有 `(K/V, layer)` 平面中的多段连续数据。原 kernel 直接使用 `block_id * logical_block_bytes` 定位地址，因此把逻辑 block 错当成了一段连续内存；GPU 和 CPU 的物理 block 数不同时，源和目标的平面步长也会不同。

修复后的 kernel：

1. 使用 CUDA grid 的第 3 维遍历所有 `(K/V, layer)` 平面。
2. 每个平面只复制该 block 对应的连续数据段。
3. 分别使用源、目标张量的物理 block 数计算平面地址。
4. 检查张量连续性、block 形状和字节数是否符合预期布局。

## 修复后结果

```text
test_non_identity_swap_out_copies_logical_blocks_only ... ok
test_round_trip_can_restore_to_different_gpu_blocks ... ok

Ran 2 tests
OK
```

## 结论

实验复现并修复了 swap kernel 对 KV cache 多维布局处理错误的问题。非同编号换出、恢复到不同 GPU block、未映射 block 保持不变三项性质均得到验证，测试可继续作为回归保护。
