# Zero-copy 与 cudaMemcpy2DAsync 对照实验

## 实验目的

比较当前占用 GPU SM 的 zero-copy kernel 与使用 copy engine 的 `cudaMemcpy2DAsync`，重点观察单独传输性能和与 GPU 计算并发时的总时间。

## 实现

新增 `copy_blocks_2d` CUDA 扩展接口。每个 mapping 提交一次二维异步复制：

- `width`：每个 `(K/V, layer)` 平面中一个 block 的连续字节数。
- `height`：`K/V × layer` 平面数。
- `src_pitch`：源 cache 的物理 block 数乘以 `width`。
- `dst_pitch`：目标 cache 的物理 block 数乘以 `width`。

接口使用 CPU `int64 [N, 2]` mapping tensor，由 CPU 读取 block 编号并提交复制命令。Host cache 必须使用 pinned memory。

## 正确性

测试覆盖：

- zero-copy 非同编号 GPU→CPU 换出。
- zero-copy 恢复到不同 GPU blocks。
- memcpy2d 非同编号 GPU→CPU 换出。
- memcpy2d 恢复到不同 GPU blocks。
- 两种方法均检查未映射 blocks 保持不变。

```text
Ran 4 tests
OK
```

## 实验配置

- GPU：空闲的 NVIDIA A800 80GB PCIe
- KV cache：FP16，28 层，block size 256，8 个 KV heads，head dimension 128
- 每个逻辑 block：28 MiB
- 计算负载：`8192 × 8192` FP16 矩阵乘法
- 每组预热 10 次，测量 50 次并报告中位数
- 方向：GPU→CPU 和 CPU→GPU
- Mappings：1、2、4、8

## GPU→CPU 结果

| Mappings | Zero-copy 传输 | Memcpy2d 传输 | Zero-copy 并发总时间 | Memcpy2d 并发总时间 | Memcpy2d 总时间改善 |
|---:|---:|---:|---:|---:|---:|
| 1 | 1.176 ms | 1.229 ms | 5.544 ms | 4.530 ms | 20.9% |
| 2 | 2.248 ms | 2.351 ms | 6.399 ms | 4.336 ms | 34.9% |
| 4 | 4.483 ms | 4.585 ms | 8.403 ms | 4.664 ms | 46.7% |
| 8 | 8.957 ms | 9.079 ms | 12.812 ms | 9.254 ms | 30.5% |

GPU→CPU 单独传输性能接近。Memcpy2d 有效带宽为 22.25～24.09 GiB/s，zero-copy 为 23.26～24.42 GiB/s，但 memcpy2d 重叠效率达到 97.2%～98.7%。

## CPU→GPU 结果

| Mappings | Zero-copy 传输 | Memcpy2d 传输 | Zero-copy 并发总时间 | Memcpy2d 并发总时间 | Memcpy2d 总时间改善 |
|---:|---:|---:|---:|---:|---:|
| 1 | 1.187 ms | 2.067 ms | 5.543 ms | 4.390 ms | 30.8% |
| 2 | 2.360 ms | 3.416 ms | 6.555 ms | 4.251 ms | 44.2% |
| 4 | 4.700 ms | 6.570 ms | 8.738 ms | 6.537 ms | 38.7% |
| 8 | 9.384 ms | 10.908 ms | 13.332 ms | 10.905 ms | 27.4% |

CPU→GPU 的 memcpy2d 单独传输比 zero-copy 慢，但重叠效率达到 94.5%～99.8%，并发总时间仍明显更短。

## 结论

当前 zero-copy kernel 的单独传输速度较好，但与计算几乎串行；memcpy2d 能把大部分传输隐藏在独立 GPU 计算后面。对于当前同步正式路径，直接用 memcpy2d 全面替换会增加 swap-in 延迟。对于后续跨轮异步流水线，memcpy2d 是更合适的传输实现。

下一步应设计 block 的 `pending_free` 生命周期和 CUDA Event，在传输完成前禁止 GPU/CPU blocks 被重新分配。先实现最小的异步 swap-out 状态机，再做端到端正确性与延迟测试。
