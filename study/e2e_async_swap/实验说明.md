# 真实模型同步与异步 Swap 对照实验

## 实验问题

在相同模型、请求和 KV Cache 容量下，安全异步和完全异步 swap 是否能改善吞吐、TTFT 或 TPOT，以及改善是否伴随新的尾延迟或输出差异。

## 控制变量

- 同一模型目录和单张 GPU。
- 同一随机种子生成固定长度的 token 请求。
- 基准内部使用严格 argmax 采样，要求两组总输出摘要一致，并报告逐请求输出匹配数。
- 同样的 GPU 显存比例、CPU swap 空间和最大并发数。
- 使用 num-gpu-blocks 显式固定物理 KV block 数，避免两次模型初始化的瞬时显存差异改变实验容量。
- 同步、安全异步、完全异步分别在独立进程运行。
- 重复实验交替三种方案的执行顺序，降低温度、时钟和后台负载顺序造成的偏差。

## 指标

- 总生成吞吐。
- 逐请求 TTFT 的均值、P50 和 P95。
- 逐请求 TPOT 的均值、P50 和 P95。
- swap-in、swap-out block 数。
- 等待 CUDA event 且没有模型 batch 的调度轮数。
- CUDA peak allocated memory。

## 运行

先用小负载确认脚本和模型兼容，再提高并发并降低 gpu-memory-utilization，直到同步和异步两组都产生 swap。

示例命令：

    uv run python study/e2e_async_swap/run_compare.py \
      --model /path/to/Qwen3-model \
      --num-requests 48 \
      --input-len 512 \
      --output-len 128 \
      --num-gpu-blocks 80 \
      --gpu-memory-utilization 0.10

结果分别写入 results/sync.json、results/async.json 和 results/comparison.json。

单次结果只能说明该模型、硬件和负载下的表现。正式结论至少重复三次，并报告均值与波动。

三方案压力矩阵入口：

    uv run python study/e2e_async_swap/run_matrix.py \
      --model /path/to/Qwen3-model \
      --results-dir study/e2e_async_swap/results/formal \
      --gpu-blocks 32,24,20 \
      --repetitions 3

三种方案分别是 sync、safe_async 和 full_async。full_async 会打开仅用于研究的 unsafe_async_swap_out。
