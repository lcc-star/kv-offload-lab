# 真实模型异步 KV Swap 实验报告

## 实验目的

验证异步 swap 已经进入真实模型执行路径，并检查以下三件事：

1. 同步与异步路径在确定性采样下逐请求输出一致。
2. 两组使用完全相同的 GPU KV block 数并实际触发换入换出。
3. 没有可运行模型 batch 时不会持续轮询 CUDA event。

## 环境与负载

- GPU：NVIDIA A800 80GB。
- 模型：Qwen3-1.7B，本地模型路径不提交。
- GPU KV blocks：固定为 20。
- 请求：12 个，每个输入 512 tokens、输出 8 tokens。
- CPU swap：2 GiB。
- 采样：严格 argmax。

测试运行时 GPU 上存在其他任务，因此本轮用于正确性和功能验收，不用于正式性能结论。

## 发现的问题

最初同时允许 D2H swap-out、H2D swap-in 与模型计算重叠。压力测试中，同步和异步路径有 1/12 个请求从第二个生成 token 开始分叉。

方向隔离结果：

| 诊断配置 | 与同步基线匹配 | 结论 |
| --- | ---: | --- |
| D2H、H2D 都不等待 | 11/12 | 存在并发正确性问题 |
| 只等待 H2D | 11/12 | 问题仍存在 |
| 只等待 D2H | 12/12 | 输出恢复一致 |
| D2H、H2D 都等待 | 12/12 | 输出一致 |

因此当前实现采用正确性优先的边界：D2H swap-out 等待自身 event，H2D swap-in 仍可与其他请求的模型计算重叠。

## 忙轮询修复

异步路径原先在只有 pending transfer、没有模型 batch 时不断调用 event.query。一次短实验出现 1352 个 pending-only steps。

修复后，如果调度器没有模型计算和新传输可以提交，就等待一个 pending event 并立即回收资源。相同负载下 pending-only steps 降为 3。

## 最终验收结果

| 指标 | 同步 | 异步 |
| --- | ---: | ---: |
| GPU KV blocks | 20 | 20 |
| swap-out blocks | 12 | 12 |
| swap-in blocks | 12 | 12 |
| 调度步数 | 26 | 29 |
| pending-only steps | 0 | 3 |
| 输出匹配请求 | 12/12 | 12/12 |
| 吞吐 | 119.684 tok/s | 120.052 tok/s |
| TTFT P95 | 382.849 ms | 350.646 ms |
| TPOT P95 | 79.515 ms | 83.401 ms |

吞吐、TTFT 和 TPOT 来自共享 GPU 上的一次短实验，只证明采集链路可用。正式性能结论需要独占 GPU、固定 clocks，并至少重复三次。

## 当前结论

单卡异步 H2D swap-in 已接入真实 Qwen3 推理路径，并通过逐 token 输出一致性验证。D2H overlap 尚未达到正确性要求，当前版本没有启用。下一阶段应使用 CUDA event 时间线或 Nsight Systems 查明 D2H overlap 的实际冲突对象，再决定能否安全恢复双向重叠。
