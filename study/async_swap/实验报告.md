# 单卡异步 KV Swap 实验

## 目标

把已经验证过的 cudaMemcpy2DAsync 和 pending block 生命周期接入实际推理调度路径。在 CPU 与 GPU 传输完成前，请求和物理块都不能被再次调度或释放。

本阶段只实现单 GPU。通过 async_swap=True 开启；默认值仍为 False，原同步路径保持可用。

## 实现

- 调度器新增 SWAPPING_OUT、SWAPPING_IN 两个中间状态。
- swap-out 提交后继续占用 GPU block，CUDA event 完成后才释放 GPU block。
- swap-in 提交后同时保留 CPU 源 block 和 GPU 目标 block，CUDA event 完成后才释放 CPU block，并把请求转为 RUNNING。
- ModelRunner 使用独立 CUDA stream 提交 cudaMemcpy2DAsync，模型计算仍运行在默认 stream。
- 同一轮可同时提交 swap 和模型计算；没有可运行请求时也允许只提交传输。
- 调度器为刚换入且即将跨 block 边界的请求预留 append block，避免恢复完成后立即再次被换出。

## 正确性约束

1. PENDING 状态的 GPU 和 CPU block 不可重复分配。
2. 请求只有在对应 CUDA event 完成后才能离开中间状态。
3. swap-in/out 的逻辑 block 数据必须逐元素一致。
4. async_swap=True 只允许 tensor_parallel_size=1。

## 验证

- study/scheduler_repro/test_scheduler.py：CPU 状态机与调度边界测试。
- study/async_swap/test_async_scheduler_cuda.py：实际 CUDA stream、event、数据复制与正式调度器的集成测试。
- study/swap_kernel_repro/test_swap_kernel.py：非恒等映射和往返复制的数据正确性测试。

性能收益需要在真实模型和并发负载下测量。这里完成的是异步执行所需的正确性基础，不把 event 完成等同于严格的延迟上限。
