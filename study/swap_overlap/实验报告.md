# Swap 与计算重叠微基准

## 实验目的

测量当前 zero-copy swap kernel 与独立 GPU 计算放入不同 CUDA streams 后，能否隐藏 KV 搬运时间，为是否实现跨轮异步调度提供依据。

## 实验配置

- GPU：NVIDIA A800 80GB PCIe
- KV cache：FP16，28 层，block size 256，8 个 KV heads，head dimension 128
- 每个逻辑 KV block：28 MiB
- 计算负载：`8192 × 8192` FP16 矩阵乘法
- 使用无其他计算任务的第二张 A800
- 预热 10 次，正式测量 50 次，报告中位数
- 使用 CUDA Event 测量，双流总时间等待 swap 与 compute 两个完成事件

实验对每组 mapping 分别测量 swap、compute、同流串行和双流并发，并在计时前逐 block 校验换出数据。

## 实验结果

| Mappings | 数据量 | Swap | 有效带宽 | Compute | 串行 | 双流并发 | 重叠效率 | 总时间改善 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 28 MiB | 1.170 ms | 23.37 GiB/s | 4.400 ms | 5.566 ms | 5.536 ms | 2.6% | 0.5% |
| 2 | 56 MiB | 2.247 ms | 24.34 GiB/s | 4.209 ms | 6.442 ms | 6.412 ms | 1.3% | 0.5% |
| 4 | 112 MiB | 4.482 ms | 24.40 GiB/s | 4.127 ms | 8.598 ms | 8.375 ms | 5.4% | 2.6% |
| 8 | 224 MiB | 8.955 ms | 24.43 GiB/s | 4.116 ms | 13.062 ms | 12.781 ms | 6.8% | 2.2% |

原始结果保存在 `results.csv`。有效带宽在 mapping 数增加后稳定在约 24.4 GiB/s。

## 结论

当前 zero-copy kernel 与矩阵计算放入不同 streams 后没有获得显著重叠，四组总时间改善为 0.5%～2.6%。该 kernel 使用 GPU SM 访问映射的 pinned host memory，会和模型计算竞争 SM、内存系统与 PCIe 路径；增加 stream 不能自动形成接近 `max(T_swap, T_compute)` 的理想并发。

因此现在不适合直接为正式调度器引入 `pending_free`、跨轮 Event 和异步状态机。下一项实验应建立 `cudaMemcpyAsync` 对照，判断 copy engine 对分散 KV block 的多段传输能否在带宽和计算重叠方面优于当前 kernel。
