# Pending Block 状态机实验

## 实验目的

在不修改正式 `BlockManager` 的前提下，验证异步 KV swap 所需的两阶段资源生命周期，确保 CUDA 搬运完成前 GPU 和 CPU blocks 不会被提前复用。

## 状态设计

Block 使用四种互斥状态：

```text
FREE
USED
PENDING_FREE
PENDING_WRITE
```

请求使用：

```text
RUNNING
SWAPPING_OUT
SWAPPED
SWAPPING_IN
```

每个 `PendingSwap` 记录请求、方向、GPU blocks、CPU blocks、Event 和操作状态。操作只能从 `PENDING` 进入 `COMMITTED` 或 `ABORTED`，结束后从 active pending 集合移除。

## 两阶段转换

Swap-out reserve：

```text
GPU: USED → PENDING_FREE
CPU: FREE → PENDING_WRITE
请求: RUNNING → SWAPPING_OUT
```

Swap-out commit：

```text
GPU: PENDING_FREE → FREE
CPU: PENDING_WRITE → USED
请求: SWAPPING_OUT → SWAPPED
```

Swap-in reserve：

```text
CPU: USED → PENDING_FREE
GPU: FREE → PENDING_WRITE
请求: SWAPPED → SWAPPING_IN
```

Swap-in commit：

```text
CPU: PENDING_FREE → FREE
GPU: PENDING_WRITE → USED
请求: SWAPPING_IN → RUNNING
```

Abort 执行相反转换，恢复传输开始前的有效副本和请求状态。

## 不变量

- 每个 block 在任意时刻只有一个状态和一个所有者。
- `FREE` block 没有所有者，所有非 `FREE` block 必须有所有者。
- Pending operation 中记录的 blocks 必须处于对应 pending 状态并属于该请求。
- Pending blocks 不计入可分配数量。
- 已完成或回滚的操作不能重复提交。
- 不同 Event 可以乱序完成，不需要等待队头操作。

## 真实 CUDA Event 集成

最小 GPU 集成测试使用 28 层、每个逻辑 block 28 MiB 的 FP16 KV cache，在独立 CUDA stream 上通过 `copy_blocks_2d` 完成：

```text
GPU blocks [0,1] → CPU blocks [2,3]
CPU blocks [2,3] → GPU blocks [4,5]
```

测试不调用 `Event.synchronize()`，而是循环执行 `event.query()` 驱动的 `reclaim_completed()`。验证结果：

- Event 回收前，源和目标 blocks 均保持 pending 且不能重新分配。
- 换出完成后，原 GPU blocks 才能分配给新请求。
- 换入完成后，原 CPU blocks 才能分配给新请求。
- 恢复到不同 GPU block 编号后，两个 block 的内容分别保持为 11 和 22。

## 限制与下一步

当前实验已经连接真实 `torch.cuda.Event` 和 CUDA 搬运，但仍是独立测试，没有修改正式推理路径。下一步应设计 tensor parallel 的完成条件：同一逻辑 swap 只有在所有 rank 的 Event 都完成后才能提交 block 状态。完成多 rank Event 聚合测试后，再决定是否接入正式 `Scheduler` 与 `BlockManager`。
